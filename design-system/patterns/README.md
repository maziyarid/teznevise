# Editorial patterns

## Research margin

Desktop articles place the primary reading column on the physical right and a bounded context rail on the physical left. The rail may contain the table of contents, author, evidence, or related actions. Below 900px it follows the article in one column.

## Evidence strip

Use a compact horizontal group for source, reading time, update date, and review status. It must carry real information; decorative statistics are prohibited.

## Magazine index

Archive pages use a flexible editorial grid with one featured story and consistently structured article cards. Image prominence follows content priority rather than alternating for decoration.

## Service landing

Use one decisive outcome, a short evidence section, process steps only when genuinely sequential, and one primary conversion action. Avoid generic icon-card walls.

## Tool workspace

Keep input, explanation, result, validation, and methodology visually distinct. Results must remain understandable without color and announce asynchronous changes to assistive technology.

## Documentation

README and architecture documents use the same vocabulary: Evergreen, Ink, Mint, Paper, Mist; research margin; evidence strip; `tz-*` contracts. This prevents design intent from drifting between PHP, WordPress editor, and the companion frontend.
